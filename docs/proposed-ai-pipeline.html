Propozycja V1 · po decyzji CTO

AI dokładamy do pipeline'u, który już jest

Bez nowej kolejki, workerów i migracji bazy. Funkcje Magdy powstają jako moduły obecnego FastAPI, a każdy wynik wraca w odpowiedzi na request.

Granica architektoniczna V1 Zostają dwa serwisy: Next.js i FastAPI. Zostaje SQLite. OpenAI nie jest osobnym serwisem aplikacji.

1. Raport podstawowy — synchronicznie

Wejście CV lub mały batch

Obecny upload Next.js.

→
FastAPI Istniejący endpoint

Jeden request do zakończenia analizy.

→
Ingestion PDF / DOCX

Tekst, strony i minimalny Markdown.

→
Analiza Reguły + OpenAI

Osobny kontekst dla każdego CV.

→
Wynik Report + SQLite

JSON, HTML, dowody i checklista flag.

2. Dodatkowe sprawdzanie — osobny request po kliknięciu

Sprawdź firmy
Sprawdź edukację
Sprawdź LinkedIn
→
To samo FastAPI Research endpoint

Cache SQLite → OpenAI Web Search → walidacja → zapis.

→
Odpowiedź Zaktualizowany raport

Loading trwa do końca requestu. Błąd można ponowić.

Wszystkie karty Magdy zostają

Dane kontaktowe, lokalizacja, firmy, uczelnie, LinkedIn i zbiorcza checklista flag.

Świadomy limit V1

Batch działa po kolei. Limit plików i timeout ustalimy na podstawie pomiarów.

Dopiero później, jeśli potrzebne

Kolejka, workery, wznawianie i nowa baza wymagają osobnej zgody oraz danych z V1.
